# Constraint Equivalence Report — Instructions

## Overview

`scripts/diff_constraints.py` builds a PR comment that shows exactly which
constraints changed across a range of commits. The comment lives on a GitHub PR
and includes:

- A **summary table** (commits analyzed, pairs with changes, etc.)
- Per-commit **change sections**, each with:
  - A header linking to the GitHub compare diff (`prev...curr`)
  - **Updated** constraints: a table with the new expression (linked to the
    commit diff in the PR), a short file path (linked to the blob), and an
    optional remark
  - **Added / Removed** constraints: same format
  - **Count-changed** constraints (multiplicity changed, fingerprint identical)
- Sections with >12 changes are wrapped in a `<details>` block

## File layout

```
air/constraint_dumps/
  XX_<hash>_dump.txt        # constraint fingerprint dump (generated by recorder)
  XX_<hash>_sources.json    # JSON sidecar: {fp_key: {source_expr, file, line, function}}
  XX_YY_diff.txt            # text diff between consecutive dumps
  interpretations.json      # human/AI-written remarks per commit
  pr_comment.md             # generated markdown (posted to GitHub)
```

## Generating / updating the PR comment

### Full run (build every commit)

Always use the full commit range for this PR, starting from `0d20707a7c`
(the commit that added the constraint recorder):

```bash
python3 scripts/diff_constraints.py 0d20707a7c HEAD --pr-comment <PR>
```

This checks out each commit, builds, runs the recorder, extracts source
expressions, saves dumps + JSON sidecars, and posts the comment.

### Extract source expressions only (no build)

If dumps already exist but JSON sidecars are missing:

```bash
python3 scripts/diff_constraints.py --extract-sources
```

This checks out each commit, reads the source files to extract expressions, and
writes `*_sources.json` sidecars. No Rust build is performed.

### Regenerate the PR comment from existing data

```bash
python3 scripts/diff_constraints.py --regenerate --pr-comment <PR>
```

This loads dumps + JSON sidecars + `interpretations.json`, generates
`pr_comment.md`, and posts/updates the comment on the given PR.

### Typical workflow after code changes

1. Run the full build (or `--extract-sources` if dumps exist)
2. Regenerate with `--regenerate` to check `pr_comment.md` locally
3. Edit `interpretations.json` to add/update remarks
4. Regenerate again with `--pr-comment <PR>` to post

## PR comment format

Each commit section with constraint changes looks like:

```markdown
#### `<hash>` <commit message> ([diff](<compare_url>))

> N updated | M unchanged

**Updated:**

| Expression | Remark |
|------------|--------|
| [`chiplets/ace.rs`](<blob_url>) [`builder.assert_zero(...);`](<diff_url>) | Remark text |
```

Where:
- **`<blob_url>`** = `https://github.com/<slug>/blob/<hash>/air/src/constraints/<path>#L<line>`
  Links to the source file at that commit.
- **`<diff_url>`** = `https://github.com/<slug>/pull/<PR>/changes/<full_hash>#diff-<sha256_of_path>R<line>`
  Links to the per-commit diff in the PR, scrolling to the changed line.
- **`<compare_url>`** = `https://github.com/<slug>/compare/<prev_hash>...<curr_hash>`
  Links to the full diff between the two consecutive commits.

The `| Remark |` column only appears when `interpretations.json` has entries
for that commit.

## interpretations.json

This file maps commit hashes to remarks explaining *why* constraints changed.
Two entry types:

```json
{
  "<commit_hash>": [
    {
      "group_remark": "Explanation applying to all changes in this commit.",
      "applies_to": "all"
    }
  ],
  "<other_hash>": [
    {
      "old_fp": "base:<old_fingerprint>",
      "new_fp": "base:<new_fingerprint>",
      "remark": "Per-constraint explanation."
    }
  ]
}
```

- **Group remarks** (`applies_to: "all"`) apply to every Updated row in that
  commit. Use when the same transformation was applied uniformly.
- **Per-constraint remarks** match by `old_fp` + `new_fp` and take priority
  over the group remark for that specific row.
